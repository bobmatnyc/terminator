================================================================================
                        DI STRUCTURE (Pattern)
================================================================================

Container (dependency-injector framework)
├─ Singletons (expensive resources)
│  ├─ Settings (configuration)
│  ├─ UnifiedAdapter (terminal connections)
│  ├─ TerminalService (core logic)
│  ├─ OpenRouterClient (LLM connection)
│  └─ ToolRegistry (static definitions)
│
└─ Factories (lightweight/per-request)
   ├─ ITerm2Adapter, TmuxAdapter
   ├─ AnalysisService
   ├─ ToolExecutor
   └─ TerminalChatbot

Key Pattern: All dependencies injected via __init__()
             No hardcoded imports or global state
             Easy to test (inject mocks)
             Easy to extend (new adapters/tools/providers)

================================================================================
                      KEY IMPLEMENTATION CHALLENGES
================================================================================

Challenge 1: Async/Sync Mismatch
  Problem: tmux (libtmux) is sync, need async everywhere
  Solution: Use asyncio.to_thread() to wrap sync calls
  Effort: Low
  Location: server/adapters/tmux.py

Challenge 2: Session ID Fragility
  Problem: Session IDs are complex strings (tmux:sess:window:pane)
  Solution: Add validation layer, consider UUID approach
  Effort: Low
  Location: server/adapters/models.py

Challenge 3: Complex Tool Calling Loop
  Problem: LLM tool execution needs sophisticated error handling
  Solution: Extract to ToolExecutor service with retry logic
  Effort: Medium
  Location: server/llm/executor.py

Challenge 4: Testing iTerm2 (Requires Running App)
  Problem: iterm2 API requires actual iTerm2 running
  Solution: Use unit mocks, separate integration tests
  Effort: Medium
  Location: tests/unit/ and tests/integration/

Challenge 5: Prompt Detection Heuristics
  Problem: Shell prompts vary ($, #, >, ❯, etc.)
  Solution: Keep POC patterns, make configurable
  Effort: Low
  Location: server/core/analysis.py
